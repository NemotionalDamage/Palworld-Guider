# Phase G6 Knowledge Maintenance And Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep the guide trustworthy across game updates and long sessions by adding version compatibility checks, knowledge audit and update workflows, answer regression suites, operations hardening, and comprehensive documentation.

**Architecture:** A new `guide-maintenance` crate provides version checking, knowledge auditing, and batch validation as Rust functions and a CLI. A new `guide-regression` crate provides end-to-end answer regression tests. Log rotation and performance budgets are added to `guide-server`. Documentation covers installation, configuration, troubleshooting, data updates, deployment, and operations.

**Tech Stack:** Rust stable, existing `game-knowledge`, `guide-core`, `knowledge-index`, `guide-tools`, `guide-agent`, `guide-server`, `guide-planner`, `state-snapshot`, serde/serde_json.

**Spec:** `AGENTS.md` Phase G6.

## Global Constraints

- Execute only Phase G6; no new game integration, save parsing, server API, adapter, mutation, or semantic vector search.
- Every new behavior is added through a failing test first.
- Run `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `git diff --check` before claiming completion.
- No secrets, credentials, or machine-specific paths in documentation.
- Documentation must describe the current codebase, not aspirational features.

### Task 2: Answer Regression Suites

**Files:**
- Create: `crates/guide-regression/Cargo.toml`
- Create: `crates/guide-regression/tests/lookup_regression.rs`
- Create: `crates/guide-regression/tests/calculator_regression.rs`
- Create: `crates/guide-regression/tests/retrieval_regression.rs`
- Create: `crates/guide-regression/tests/grounding_regression.rs`
- Create: `crates/guide-regression/tests/version_regression.rs`
- Modify: `Cargo.toml`

**Interfaces:**
- Consumes: `GuideEngine`, `KnowledgeStore`, `KnowledgeIndex`, `ToolRegistry`, `GuideAgent`, `ToolEnvelope`, `AnswerDraft`, `FactSheet`, `render`.

- [ ] **Step 1: Write lookup regression tests**

Tests that:
- `lookup item wood` returns `ITEM_WOOD` with provenance.
- `lookup item 木` (Chinese alias) resolves to `ITEM_WOOD`.
- `lookup pal lamball` returns `PAL_LAMBALL` with work suitability and drops.
- `lookup technology "level 2"` returns the technology with unlocked recipes.
- `lookup recipe "pal sphere"` returns the recipe with ingredients and station.
- Unknown item returns `Unknown` status.
- Ambiguous query returns `Ambiguous` status.

- [ ] **Step 2: Write calculator regression tests**

Tests that:
- `materials 1 wood` returns the correct material tree for a raw item.
- `materials 1 "pal sphere"` returns the correct ingredient totals.
- `shortage 5 wood --inventory wood=2` returns the correct missing quantity.
- `craftable --inventory stone=5,paldium_fragment=5` returns the correct craftable count.
- `breeding lamball cattiva` returns the correct child (or unknown if no rule).
- Cycle detection and depth limits are respected.
- Overflow and zero-quantity inputs are rejected.

- [ ] **Step 3: Write retrieval regression tests**

Tests that:
- Searching "wood" returns relevant items.
- Searching "sphere" returns the Pal Sphere.
- Searching a Chinese alias returns the target item.
- Searching a nonexistent term returns `Unknown`.
- Result limits are respected.

- [ ] **Step 4: Write grounding regression tests**

Tests that:
- A draft with valid slot references renders correctly.
- A draft with numeric literals triggers fallback.
- A draft with number words triggers fallback.
- A draft with unsupported entities triggers fallback.
- A draft with unknown slot IDs triggers fallback.
- `fallback_render` produces player-facing text without internal markers.
- Empty draft triggers fallback.

- [ ] **Step 5: Write version-warning regression tests**

Tests that:
- A matching configured game version produces no version warning.
- A mismatched configured game version produces a version warning in uncertainty.
- A mixed knowledge version produces a mixed-version warning.
- Version info is present in every answer envelope.

- [ ] **Step 6: Verify green**

Run: `& "$env:USERPROFILE\.cargo\bin\cargo.exe" test -p guide-regression`
Expected: all tests pass.

- [ ] **Step 7: Commit**

Run: `git -c core.autocrlf=false add crates/guide-regression Cargo.toml; git commit -m "phase g6: add guide-regression crate with answer regression suites"`
