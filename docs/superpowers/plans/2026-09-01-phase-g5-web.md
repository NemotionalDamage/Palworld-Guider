# Phase G5 Web Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved loopback Web milestone for the integrated guide without enabling any runtime game integration.

**Architecture:** `guide-server` adds an Axum transport layer around the existing bounded Rust guide core. In-memory sessions own rolling rate windows, bounded follow-up text, snapshot metadata, and cancellation handles; all facts, calculations, planning, provenance, and uncertainty continue to come from `GuideAgent` and `ToolRegistry`.

**Tech Stack:** Rust stable, Axum, Tower/Tower HTTP, Tokio, serde/serde_json, existing `guide-agent`, `guide-tools`, `state-snapshot`, `knowledge-index`, and `game-knowledge`.

**Spec:** `docs/superpowers/specs/2026-09-01-phase-g5-design.md`

## Global Constraints

- Execute only the approved G5 Web milestone; no private-server REST, UE4SS, save reading, game-process access, Tauri/Discord/QQ adapter, or mutation path.
- Bind only `127.0.0.1`; allow the port and data path to be configured explicitly.
- Persist no sessions, snapshots, provider requests, answers, credentials, or logs.
- Limit JSON bodies, JSON depth, question length, history, sessions, asks, snapshot imports, timeout, and cancellation to fixed safe bounds.
- Snapshot responses expose only schema version, source kind, game version, freshness, and missing fields.
- Provider credentials stay in environment variables and never appear in responses.
- Every new production behavior is added through a failing test first.
- Run `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `git diff --check` before claiming completion.

**Interfaces:**
- Produces: `GuideServerState`, `GuideServer::new(agent, limits)`, `GuideServer::router()`, `ApiError`, cancellation registry.
- Consumes: `SessionStore`, `GuideAgent::set_state_snapshot`, `GuideAgent::ask_with_cancellation`.
- Routes: `GET /health`, `POST /api/sessions`, `GET /api/sessions/{session_id}`, `POST /api/sessions/{session_id}/snapshots`, `POST /api/sessions/{session_id}/ask`, `POST /api/cancellations/{token}`, and `GET /`.

- [x] **Step 1: Write failing endpoint tests**

Use `tower::ServiceExt::oneshot` with `axum::body::Body` and assert:

```rust
#[tokio::test]
async fn health_is_dependency_free() {
    let response = server.router().oneshot(get("/health")).await.unwrap();
    assert_eq!(response.status(), StatusCode::OK);
    assert_eq!(json_body(response).await, json!({"status": "ok"}));
}
```

Also cover:

- Session creation returns an opaque ID and expiry but no provider or path data.
- Missing/expired session returns a typed `404`.
- Invalid schema, wrong source, future capture time, unknown field, oversized body, and excessive JSON depth return typed `400`/`413` errors.
- Valid snapshot import returns only safe metadata and can be observed by a scripted state-aware agent answer.
- Ask requires non-empty text of at most 2,000 characters and returns the complete `AgentAnswer` envelope.
- Ask history is bounded and returned by `GET /api/sessions/{session_id}`.
- Ask and snapshot quotas return typed `429` envelopes.
- Static UI contains question, snapshot, provenance, uncertainty, and error regions and references no external origin.

- [x] **Step 2: Verify red**

Run `cargo test -p guide-server api`; expected failures identify missing router modules and routes.

- [x] **Step 3: Implement routes and validation**

Use `RequestBodyLimitLayer::new(65_536)`, typed request/response structs, depth check before snapshot deserialization, safe error envelopes, in-memory state, and `include_str!`-served minimal HTML/JavaScript. Keep provider calls out of session-map critical sections.

- [x] **Step 4: Verify green**

Run `cargo test -p guide-server api`; then format all changed files.

- [x] **Step 4: Verify green**

Run `cargo test -p guide-server runtime`, followed by the full `guide-server` test suite.
