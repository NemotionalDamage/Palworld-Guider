# Phase G3 Hybrid Retrieval And Grounded LLM Guide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer natural-language questions through bounded Rust tool use with lexical retrieval, typed providers, and provenance-bearing grounded answers.

**Architecture:** Add `knowledge-index` (Tantivy over deterministic structured summaries), `guide-tools` (typed registry, JSON schemas, envelopes, budgets), `provider` (OpenAI-compatible, Ollama, and mock chat adapters), and `guide-agent` (bounded loop that publishes only registry tools and synthesizes from tool evidence). Exact lookup stays ahead of lexical retrieval; vector search is deferred.

**Tech Stack:** Rust stable, existing `game-knowledge` and `guide-core`, `tantivy`, `reqwest` blocking HTTP with rustls, `serde_json`, integration tests.

**Spec:** `AGENTS.md` Phase G3 and the Runtime Guide Prompt.

## Global Constraints

- Execute G3 only; no game observer, save reader, server API, adapter, dynamic state, Web server, or mutation path.
- Facts come only from reviewed knowledge; the LLM classifies intent, selects tools, and phrases answers.
- Deterministic tools own all recipes, shortages, craftable counts, and breeding results.
- The model sees only registry-published tools and schemas and cannot bypass validation.
- Envelopes carry status, data, provenance, version, uncertainty, and errors.
- Timeouts, cancellation, malformed calls, provider failures, and budget exhaustion stay clear and non-fatal.
- Unknown, stale, and conflicted knowledge stays visible; secrets stay environment-only.
- `cargo test` runs offline through the mock provider and deterministic fixtures.
