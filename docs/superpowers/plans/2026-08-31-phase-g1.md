# Phase G1 Knowledge Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the reviewed, versioned, offline knowledge foundation required by Phase G1.

**Architecture:** A Rust workspace will contain one `game-knowledge` crate that owns typed JSONL records, strict validation, provenance propagation, and reference-integrity checks. Canonical source metadata and reviewed facts will remain diffable JSONL files under `data/reviewed`; no database or runtime guide is introduced.

**Tech Stack:** Rust stable, `serde`, `serde_json`, standard-library validation, inline Rust tests, JSONL canonical data.

**Spec:** `AGENTS.md` Phase G1 and `docs/knowledge-source-policy.md`.

## Global Constraints

- Execute Phase G1 only; no CLI, retrieval, LLM, adapter, server, or dynamic state.
- Every persisted game fact carries source, version, date, reviewer, review status, confidence, and change risk where relevant.
- Invalid or incomplete records fail validation.
- Conflicts remain explicit rather than being silently selected.
- Canonical data remains versioned, diffable JSONL.
- Do not store model-derived facts, raw page dumps, assets, or wholesale copyrighted text.
- Use supplied sources only after registration in `docs/reference-data/source-log.md`.
