# Phase G2 Deterministic Guide CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove deterministic lookup and calculation correctness without an LLM or live game state.

**Architecture:** Add a `guide-core` library and binary that consumes the validated `game-knowledge` store. The library will own normalized name resolution, exact lookups, material trees, shortages, craftable counts, and breeding traversal; the binary will remain a thin offline JSON CLI. Every successful answer carries provenance and version information, while missing, stale, ambiguous, cyclic, or invalid inputs produce explicit non-fabricated outcomes.

**Tech Stack:** Rust stable, `serde`, `serde_json`, existing `game-knowledge` JSONL loader, integration tests, and the Cargo binary test harness.

**Spec:** `AGENTS.md` Phase G2 and `docs/schemas/knowledge-v1.md`.

## Global Constraints

- Execute Phase G2 only; no LLM, retrieval index, provider, adapter, server, save reader, or dynamic-state source.
- Keep every user-visible fact grounded in the reviewed knowledge store.
- Deterministic Rust functions own all numerical and graph calculations.
- Missing records return `unknown`; stale or conflicting knowledge remains visible.
- Names, aliases, ambiguous matches, invalid quantities, cycles, depth limits, duplicate ingredients, multiple outputs, by-products, and alternative recipes must have regression coverage.
- The CLI must work completely offline from canonical JSONL data.
